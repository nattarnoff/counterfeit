Atom

Button

Primary and secondary actions built on the native button element.

Usage: trigger actions with the native <button> element, then add progressive enhancement only for the action itself.

Choose an action to preview button behavior.

<button class="cf-button cf-button--primary" type="button">Save</button>
<button class="cf-button cf-button--secondary" type="button">Cancel</button>
.cf-button {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  border-radius: var(--cf-radius-md);
}

.cf-button--primary {
  background: var(--cf-color-text);
  color: var(--cf-color-bg);
}
const buttonStatus = document.querySelector('[data-button-status]');

document.querySelectorAll('[data-demo-button]').forEach((button) => {
  button.addEventListener('click', () => {
    buttonStatus.textContent = `${button.textContent} activated.`;
  });
});
Button ARIA requirements
Required ARIA Expectation
None by default Use the native <button> element and only add aria-pressed when the control is a toggle.
Button keyboard expectations
Key Expectation
Tab Moves focus to the button in document order.
Enter / Space Activates the focused button.

Warnings

Do not replace buttons with links when the control performs an on-page action.

Atom

Input

Single-line text input with persistent labeling and hint text.

Usage: pair every input with a visible label and only use status text when the value or validation state changes.

Start typing to see the input event update.

<label class="cf-field" for="demo-name">
  <span class="cf-field__label">Display name</span>
  <input class="cf-field__control" id="demo-name" type="text" />
</label>
.cf-field {
  display: grid;
  gap: var(--cf-space-xs);
}

.cf-field__control {
  border: 1px solid var(--cf-color-border);
  background: var(--cf-color-surface-strong);
}
const demoNameInput = document.querySelector('#demo-name');
const demoNameStatus = document.querySelector('#demo-name-status');

demoNameInput.addEventListener('input', () => {
  demoNameStatus.textContent = demoNameInput.value
    ? `Preview value: ${demoNameInput.value}`
    : 'Start typing to see the input event update.';
});
Input ARIA requirements
Required ARIA Expectation
aria-describedby Reference hint or status text only when the additional guidance improves understanding.
Input keyboard expectations
Key Expectation
Tab / Shift+Tab Moves focus in and out of the input.
Text editing keys Follow native browser editing behavior without custom interception.

Warnings

Never rely on placeholder text as the only label or instruction for the field.

.cf-nav__list {

  gap: var(--cf-space-md);

}
No JavaScript required for standard navigation links.
Navigation ARIA requirements
Required ARIA Expectation
aria-label Label the navigation landmark when multiple nav regions are present.
Navigation keyboard expectations
Key Expectation
Tab Moves focus from link to link in reading order.
Enter Activates the focused destination.

Warnings

Avoid custom keyboard interactions for simple site navigation; native links already meet the need.

NewsletterDemo

Progressively enhanced form example with validation feedback and live status updates.

Usage: keep the native form submission model, validate required fields, and reserve live regions for concise confirmation or error text.

Newsletter form demo

This demo keeps validation, hints, and status messaging in one documented component.

<form class="cf-newsletter__form" data-demo-form>
  <input id="email" type="email" required aria-describedby="email-hint form-status" />
  <button type="submit">Join updates</button>
  <p id="form-status" aria-live="polite"></p>
</form>
.cf-newsletter {
  display: grid;
  gap: var(--cf-space-lg);
}

.cf-newsletter__fields {
  display: flex;
  gap: var(--cf-space-md);
  flex-wrap: wrap;
}
demoForm.addEventListener('submit', (event) => {
  event.preventDefault();

  if (!emailInput.validity.valid) {
    formStatus.textContent = 'Enter a valid email address before submitting.';
    return;
  }

  formStatus.textContent = `Demo subscription captured for ${emailInput.value}.`;
});
NewsletterDemo ARIA requirements
Required ARIA Expectation
aria-describedby and aria-live="polite" Associate hints and status updates without interrupting the user during typing.
NewsletterDemo keyboard expectations
Key Expectation
Tab Moves through the field and submit button in source order.
Enter Submits the form from the input or button according to native browser behavior.

Warnings

Keep submission feedback short and avoid replacing inline errors with color-only cues.

Best Practices

Document the decisions that make components durable in production.

These seven topics frame the review checklist for teams building with Counterfeit.

Design

Keep contrast, spacing, heading structure, and focus states visible before styling variants.

Code

Start with semantic HTML, layer CSS tokens next, and add JavaScript only as progressive enhancement.

User experience

Write labels, helper text, and error messages that explain the next step without jargon.

Screen reader

Prefer native names, roles, and values; verify that announcements stay concise and ordered.

Keyboard only

Ensure every path works without a pointer and preserve visible focus at every state.

Switch

Support clear focus order, large activation targets, and predictable timing for scanning interfaces.

Speech control

Use visible labels that match accessible names so spoken commands align with what people see.

Building a Program

Accessibility programs need both implementation patterns and governance structure.

Use this area to connect component work with legal, compliance, and reporting obligations.

Legal

Track applicable laws, contractual commitments, and internal policy requirements before release planning.

Conformance

Map components and journeys to WCAG criteria, then capture evidence as issues are resolved.

Compliance

Define the review process, exception handling, and sign-off path used by engineering and procurement teams.

Reporting

Publish defect status, remediation timelines, and testing coverage in a cadence stakeholders can trust.

ACRs / VPAT

Store Accessibility Conformance Reports alongside release artifacts so product claims stay reviewable.
